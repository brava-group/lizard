# GPU frame drag, 2026-10-29

The benchmark loads `assets/app-icon/Lizard-new-icon.figcraft`, renders at 3504 × 2020 pixels and 0.614× document scale, then simulates 60 pan and 60 frame translation positions. It waits for the GPU after every frame. `--reuse-translations` keeps the prepared blur and shadow textures and shifts their world bounds when only one subtree moves.

| Path | Pan p50 | Pan p95 | Drag p50 | Drag p95 | Effect preparation p50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Rebuild effects per drag frame | 7.89 ms | 25.03 ms | 198.62 ms | 282.71 ms | 38.84 ms |
| Reuse translated GPU effects | 8.06 ms | 21.89 ms | 10.09 ms | 25.70 ms | 0.03 ms |

The cache was reused in 59 of 60 drag positions. The first position had no translation. At the final position, the cached rendering and a full GPU rebuild differed in **zero** color channels. At 1266 × 1720, the direct GPU rendering and the CPU reference differed by 0.115 color levels per channel on average (8-bit channels); the largest single-channel difference was 56. Both captures were inspected visually.

Reproduce with:

```sh
cargo build --release --manifest-path benchmarks/canvas-strategies/Cargo.toml --bin direct_vector_motion
benchmarks/canvas-strategies/target/release/direct_vector_motion --file=assets/app-icon/Lizard-new-icon.figcraft --width=3504 --height=2020 --compare-drag
benchmarks/canvas-strategies/target/release/direct_vector_motion --file=assets/app-icon/Lizard-new-icon.figcraft --width=3504 --height=2020 --compare-drag --reuse-translations
```

These numbers include a GPU fence and can vary with other GPU load. They demonstrate the cost of rebuilding effects for a translation; they do not establish a frame rate for every document or a physical pointer latency.

## Rotate and Scale preview

The same icon and 3504 × 2020 viewport were used for 60 reversing rotation positions and 60 reversing uniform Scale positions. Scale uses the editor's `scale_node` operation. Both optimized paths transform prepared effect textures on the GPU during the gesture and rebuild them at release.

| Gesture | Rebuild p50 | Rebuild p95 | GPU preview p50 | GPU preview p95 | Cache hits |
| --- | ---: | ---: | ---: | ---: | ---: |
| Rotate | 132.07 ms | 157.94 ms | 1.84 ms | 5.95 ms | 59/60 |
| Scale | 112.96 ms | 223.03 ms | 6.10 ms | 10.99 ms | 59/60 |

The final Rotate preview differed from its full GPU rebuild by 0.0020 levels per 8-bit channel on average at ultrawide resolution; Scale differed by 0.0018. Both previews were visually inspected at 1266 × 1720. Scale reuse is limited to a verified uniform subtree scale and to a 0.5×–2× texture magnification range. Outside that range or with unsupported edits, effects are rebuilt during the gesture.

## Desktop check

The release editor was opened with direct GPU rendering and `Lizard-new-icon.figcraft`. A raw window input gesture scaled the selected 1024 × 1024 frame to 1056.06 × 1056.06. The editor logged no effect preparation during the active scale move. The live GPU preview and the frame captured after pointer release differed by 0.03 levels per 8-bit RGB channel on average inside the icon crop (maximum channel difference 14). Both captures were inspected; the frame and its effects remained visible. This confirms that the editor's gesture flag reaches the GPU preview path. The test did not save the modified document.

At this stage, `cargo test -p figcraft-canvas-gpu --release --lib` passed all 14 tests, `cargo xtask layers` passed, `cargo check -p figcraft-ui-egui --target wasm32-unknown-unknown` passed, and the release editor built with `gpu-canvas-experiment`.

## Move-tool frame resize follow-up

The dedicated Scale tool uses `scale_node`, while dragging a handle with the Move tool uses `resize_node`. The earlier cache predicate recognized only the first operation. In a frame containing blur, drop shadow, and inner shadow, Move-tool resize rebuilt all three effects for every pointer update. A separate provisional path now retains unchanged child effects and stretches the resized shape's own prepared effect on the GPU until release. It covers frames, rectangles, ellipses, polygons, stars, and vectors when their edit is a verified size change and any descendants keep their geometry or move only by translation.

The same saved icon's inner frame (node 26) was resized through `resize_node` for 60 reversing positions at 1501 × 1720 pixels. Each frame waited for the GPU.

| Move-tool frame resize | p50 | p95 | Effect preparation p50 | Cache hits |
| --- | ---: | ---: | ---: | ---: |
| Rebuild each update | 96.45 ms | 311.88 ms | 28.35 ms | 0/60 |
| Reuse GPU effect textures | 1.34 ms | 5.31 ms | 0.01 ms | 59/60 |

The first position was unchanged. Final preview versus a full GPU rebuild differed by 0.0039 levels per 8-bit channel on average (maximum difference 10); both images were inspected. The preview is restricted to a single resized shape whose descendants keep their geometry or move only by translation, with width and height ratios between 0.5× and 2×. Other edits still take the full effect preparation path.

The inner rectangle with its own shadow also showed the problem. With one icon, resize p95 fell from **432.20 ms to 14.26 ms** (59/60 hits; preview/rebuild mean difference 0.0104 levels per channel, maximum 32). With a duplicated icon in the document, resizing that rectangle fell from **512.48 ms to 30.57 ms** p95 (59/60 hits). The second figure still exceeds a 16.7 ms frame budget at its tail; rendering the more complex scene remains the next bottleneck after effect preparation.

A vector layer with Gaussian blur previously missed the resize cache on all 60 positions (p95 501.19 ms). Comparing its scaled control points and handles against the editor's resize operation enabled 59/60 hits and reduced p95 to **5.58 ms**. Final preview/rebuild mean difference was 0.0180 levels per channel (maximum 17); both captures were inspected.

## Duplicate drag follow-up

The engine rebuilds the duplicate from the gesture's original document on every pointer move. The first move adds new node ids, so the existing translation predicate misses the copy and previously prepared blur and shadow textures were baked again. The direct GPU path now verifies that the new subtree has exactly the source's render inputs and differs only by a world-space translation. It binds the source's prepared GPU effect textures to the copy and prepares final textures on release. Changed geometry or styles, structural edits, and world-coordinate grain effects take the full preparation path.

The saved icon's inner frame (node 26) was duplicated beside its source and dragged through 60 reversing positions at 1501 × 1720 pixels. Each frame waited for the GPU. The document was cloned, duplicated, moved, and normalized for every position, as in the editor gesture.

| Duplicate drag | Frame p50 | Frame p95 | Document p50 | Effects p50 | Effects p95 | Cache hits |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Rebuild effects every move | 432.01 ms | 1031.42 ms | 0.05 ms | 167.62 ms | 333.40 ms | 0/60 |
| Reuse source GPU textures | 11.03 ms | 19.82 ms | 0.05 ms | 0.02 ms | 0.05 ms | 60/60 |

The last GPU preview and a full GPU rebuild were pixel-identical (maximum and mean channel difference both zero). Both captures were inspected. The remaining p95 above 16.7 ms is scene submission/rendering cost with two visible icon frames; this optimization removes the effect-rebake stall. This benchmark does not imply that document mutation itself runs on the GPU: the measured CPU document work was 0.05 ms p50.

The release GPU crate passed all 15 tests after this change, including the duplicate validation regression. The release desktop app built and opened with direct Vello GPU rendering. A fresh `cargo xtask layers` run was interrupted while compiling the debug workspace from a cleaned cache; no crate dependencies changed since the earlier passing layer check.

## Shape creation follow-up

The Draw gesture creates a new node from the interaction snapshot at each pointer position. Previously that document change rebuilt all of the saved icon's blur and shadow textures, even though the new default shape had no effect. The direct GPU renderer now keeps the existing effect textures when all cached owners retain the same render properties, world transform, and raster bounds. New effectful or masked layers and changes that invalidate an existing cache still use full preparation. The new geometry itself is drawn in the Vello GPU scene; creating the document node remains CPU work.

On the saved icon, a rectangle was drawn inside the inner frame (node 26) through 60 reversing sizes at 1501 × 1720 pixels. Each frame waited for the GPU. The engine's normalization step ran at every position.

| Rectangle creation | Frame p50 | Frame p95 | Document p50 | Effects p50 | Cache hits |
| --- | ---: | ---: | ---: | ---: | ---: |
| Rebuild effects every move | 98.21 ms | 450.54 ms | 0.02 ms | 29.90 ms | 0/60 |
| Keep unaffected GPU effects | 1.29 ms | 4.98 ms | 0.01 ms | 0.00 ms | 60/60 |

An ellipse and a new frame also reused effects on all 60 positions. Frame creation measured 9.85 ms p95. Ellipse creation measured 25.11 ms p95 on one trace and 5.68 ms p95 on an immediate repeat, showing run-to-run GPU contention. The last preview for all three shapes was pixel-identical to a full GPU rebuild (maximum and mean channel difference zero); the rectangle capture was visually inspected. The release GPU crate passed all 16 tests, including the new cache validation regression.

The updated release editor was opened in a separate instance with direct Vello GPU rendering. A live rectangle gesture inside the icon's inner frame showed the shape on the canvas while dragging. Its log showed no effect preparation during the pointer moves; the one later preparation followed undo, which removed the test shape. The test document was restored, and the screenshot was inspected.
