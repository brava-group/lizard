# GPU effects migration

Lizard's native canvas uses Vello GPU for supported vector geometry and wgpu for reusable effect textures by default. Native PNG, JPEG, and WebP exports use the GPU for supported sRGB content up to 4096 × 4096 pixels; unsupported content and larger exports use `figcraft-render`. SVG and PDF retain their vector exporters, and WASM uses the CPU canvas. Set `LIZARD_GPU_CANVAS_CPU=1` to use the CPU canvas or `LIZARD_GPU_EXPORT_CPU=1` to use CPU raster exports. `figcraft-render` and some other paths still use tiny-skia; removing it requires a separate renderer migration.

## Current coverage

| Content | Native direct canvas | Remaining work |
| --- | --- | --- |
| Paths, fills, strokes, text outlines, images | Vello GPU scene, with capability checks | Text style runs, masks, all blend modes, image filters, and color profiles need parity tests. |
| Vector faces with individual solid or supported gradient fills | Vello GPU; the empty face remains empty | Test overlapping faces, mixed winding, and all paint kinds. |
| Uniform and progressive layer blur | Vello filter or document-stable wgpu texture; progressive interpolation uses eight or fewer blur levels on wgpu | Most stacked effects and large or nested layers need a GPU graph. |
| Drop and inner shadows | Vello filter or cached GPU texture for supported shapes; opaque vector, ellipse, polygon, and star drop shadows with spread up to 32; a translucent solid path shadow with zero spread; stroked rectangle, ellipse, polygon, star, vector, and line shadows with spread up to 32 under the guarded stroke rules; group inner and drop shadows with nested alpha/vector masks and spread up to 32 | Rotated group inner shadows, rotated group drop shadows with spread above 8, dashed strokes with positive spread, arbitrary child effects and blend modes still need parity work. |
| Uniform and progressive background blur | Composition-order-aware GPU capture and blur for multiple visible backdrops in the native direct editor | Masks, group isolation, and large viewports need parity and latency work. |
| Noise | wgpu compute pass for isolated layers with normal blend, including rotated shapes; other cases use the faithful atlas | Mixed effects on rotated shapes, skewed shapes, and non-normal blend need parity before broadening coverage. |
| Texture scatter | Two wgpu compute caches at native 1× and 2×, selected in the normal direct canvas when the bounds align with device pixels | Fractional zoom, rotated shapes, and very large textures need view-aware GPU preparation. |
| Glass | wgpu backdrop capture, refraction, frost, highlights, and vector mask for isolated rectangle, ellipse, or vector panes within a bounded region; ordered blur/noise stacks and a guarded drop shadow, including rotated panes; a solid-filled pane with glass, blur, noise and one shadow now composites all four on GPU | Glass on groups, nested masks, clipped or very large panes, and broader shadow combinations still need GPU support and parity tests. |
| Combined layer effects | Ordered GPU passes for blur/noise in either order, longer stacks, and one drop shadow on an isolated axis-aligned shape or supported group; rotated shapes with blur and shadow, without noise | Rotated blur/noise stacks, multiple mixed shadows and non-normal blend need view-aware preparation. |

Vello GPU 0.3 performs path preparation on the CPU and rasterization/compositing on the GPU. Its filter primitives are useful, but they do not implement Lizard's entire effect model. See the [Vello architecture](https://github.com/linebender/vello/blob/main/ARCHITECTURE.md) and [Sparse Strips release notes](https://github.com/linebender/vello/releases).

The Vello filter API lists noise/turbulence, displacement, color matrix and several other primitives, but marks them as unimplemented. These cannot replace Lizard's noise, texture, or glass effects merely by switching filter types. A small `vello_cpu 0.3` shadow probe did not improve parity over the GPU route; it is not yet a verified export fallback.

## Migration contract

1. Preserve effect order and compositing order. A backdrop effect may sample only layers behind its node.
2. Use document-space cache keys for isolated, static effects. Invalidate a cache when its node, inputs, or any underlying backdrop changes.
3. Clip intermediate work to the effect's region of interest, including blur radius, spread, and shadow offset. A texture must stay within device limits at UltraWide sizes.
4. Keep pan and zoom on the same GPU device as the editor. Scene geometry is drawn at the current camera; document-stable effects may be reused as GPU textures.
5. Compare representative documents against the current renderer at multiple scales, including edited effects, masks, transparency, and export. Measure frame time, peak memory, and resize behavior on native and WASM before removing the fallback.

The cross-renderer tests include `vector_regions_parity`, `vector_shadow_parity`, `progressive_blur_parity`, `noise_gpu_parity`, and `texture_gpu_parity` in `benchmarks/canvas-strategies/src/bin/`. The grain passes use the same 64-bit cell hash as `figcraft-render`; their isolated source, compute output, and display cache stay on the GPU. The live icon test uses the opt-in feature and environment variables described in `benchmarks/canvas-strategies/RESULTS-2026-10-28.md`. The experiment must not become the default renderer or replace exports until the remaining rows pass.

The progressive layer blur fixture differs from the reference by 0.241/255 average RGB at 1× and 0.204/255 at 2×; respectively 0.091% and 0.043% of pixels differ by more than 8/255. Its cache preparation took about 24 ms on the test Mac. The progressive backdrop fixture passed sampled-pixel comparisons and took 11.15 ms on a warm 100×100 viewport. These are small fixtures, not a claim about UltraWide performance. A combined layer blur plus background blur fixture verifies that releasing temporary backdrop textures does not discard prepared layer-effect textures.

On the local Apple GPU, the axis-aligned noise cases at 1× and 2× differed by at most 1/255 per channel from the CPU reference; changing density rebuilt the cache and stayed within that error. A warm cache reuse took about 0.01 ms, compared with roughly 8–12 ms to prepare one effect. A single 2× texture cache matched exactly at 2×, while its resampled edge differed on 0.17–0.45% of pixels by more than 8/255 at 1×. A separate 1× cache reversed that result. The two-cache path now chooses the native cache at pixel-aligned 1× or 2×; its regression fixture has zero pixels differing by more than 8/255 at either zoom. Fractional scales still need a view-aware cache. These numbers are isolated-effect probes, not whole-document frame-rate claims.

The isolated noise path also passed two rotated rectangle fixtures (30° and 60°) at 1× and 2×. Mean RGB error ranged from 0.106–0.129/255, with 0.203–0.327% of pixels differing by more than 8/255. The noise shader already samples through the inverse local transform; the earlier axis-alignment restriction was unnecessary for this case. Texture scatter and ordered blur/noise stacks retain their axis-alignment checks.

The glass GPU subset matched the existing renderer within 0.383/255 mean error in the small rectangle fixture, 0.116/255 for an ellipse, and 0.059/255 for a vector. An isolated 3440×1440 viewport with a small glass pane took about 38 ms on a warm second rendering with a cropped region and reused prefix surface. First-use shader compilation remains much more expensive. An ordered two-backdrop fixture also passed sampled-pixel comparisons, but the path re-renders a prefix per backdrop and needs a multi-pane latency benchmark. Glass with a drop shadow now captures the object's own shadow in the GPU backdrop before refraction; the 1×/2× fixture passed for opaque and translucent panes, either shadow visibility setting, two effect orders and 0°/29° rotation.

Blur and noise in either order on one isolated shape and multiple low-opacity shadows on one rectangle have passing GPU-versus-reference tests. A new wgpu silhouette-clip pass hides a translucent vector's shadow inside its contour. Across fill alpha 0.25, 0.5, and 0.75 at 1× and 2×, its mean RGB error was 0.130–0.149/255 with zero pixels differing by more than 8/255. The direct renderer enables that narrow cached-shadow case; larger spread and translucent strokes still need separate implementations.

The combined blur/noise/shadow cache remains limited to axis-aligned shapes when noise is present. A rotated 1× blur/noise fixture differed from the reference by more than 3,800 pixels above 8/255, so a regression test keeps this combination on the fallback path until its intermediate texture placement and blur sampling match the reference. A rotated star with blur and shadow, in both effect-list orders, passed 1×/2× reference comparisons and now uses the GPU cache. Rotated glass panes also run ordered GPU blur/noise passes at view resolution and passed 1×/2× comparisons. For a translucent, rotated solid pane with glass, blur, noise and shadow, the direct path now composes the glass and pane paint in an offscreen GPU surface, runs the layer passes on that result, and builds its shadow from the processed texture. The user preferred the GPU look despite the compositing difference from the CPU reference. At 2× in a 960×960 viewport, the GPU result differed by more than 8/255 on 6.228% of pixels, with 0.852/255 mean RGB error; this is a deliberate visual change, not CPU parity. Six optimized warm renders of this synthetic 960×960 fixture took 53.95–81.67 ms, so the stack needs interaction-time reuse before it can run fluidly during zoom. These times include GPU queue completion at final presentation and are not a frame-rate estimate for the saved icon document.

An inner-shadow compute path now renders an opaque silhouette on Vello GPU, offsets and inverts it in wgpu, blurs it on wgpu, then masks and tints it within the original silhouette. The closed-vector fixture differed from the reference by 0.113/255 mean RGB at 1× and 0.105/255 at 2×; respectively 0.139% and 0.126% of pixels differed by more than 8/255. At fill alpha 0.5, mean error was 0.133/255 and 0.127/255 at 1× and 2×. Full ellipse, polygon, and star fixtures also passed at 2×. The cache is limited to a single inner shadow with zero spread, offsets aligned to cache pixels, no strokes or per-region fills, and a solid fill. Rectangles and frames retain their existing analytic GPU shadow path.

A group of solid-filled, gradient-filled, or stroked shapes uses a GPU texture of its composed children as the shadow silhouette. A wgpu pass combines either inner or drop shadow with that texture, so the cache draws as one layer. A separable wgpu morphology pass grows or shrinks the silhouette for spread. The fixture with overlapping children, a translucent fill, a linear gradient fill, a dashed outside stroke, a nested group, alpha and vector masks, and reduced child/group opacity passed at 1× and 2× for spread 0, ±2, ±8, ±16 and ±32. Group drop shadows also passed with `show_behind` enabled. The GPU cache limits spread to 64 cache pixels and nesting to eight levels. A rotated group drop shadow passed at zero spread; a rotated group inner shadow exceeded the parity threshold and remains on the fallback path. Diamond gradients, luminance group masks, child effects, and non-normal child blends remain on the fallback path.

The saved `Lizard-new-icon.figcraft` document rendered with all three of its visible effects on the native GPU path at 1024 and 2048 px. Against `figcraft-render`, mean RGB error was 0.798/255 and 0.764/255 respectively; 0.601% and 0.401% of pixels differed by more than 8/255. Preparation took 30.08 ms and 26.83 ms; warm GPU submission took 0.81 ms and 1.59 ms. These submission times exclude GPU readback and display presentation. Run `gpu_icon_effect_parity` in `benchmarks/canvas-strategies` to repeat the comparison; setting `LIZARD_BENCH_WRITE_PNG=1` also writes the 1× reference and GPU images to `/tmp`. This document-specific result does not imply that arbitrary effect stacks have GPU parity.

For translucent solid vectors and full ellipses, polygons, or stars, a single zero-spread drop shadow also runs on GPU when `show_behind` is enabled. The 1×/2× fixtures ranged from 0.091–0.246/255 mean RGB error, with no more than 0.003% of pixels differing by more than 8/255. A trial of geometric positive and negative inner-shadow spread on single paths differed by more than 1.3% of pixels above 8/255, so that case remains on the reference route until the offset geometry matches.

Two ordered drop shadows on opaque vector, polygon, and star shapes passed 1×/2× parity fixtures; 0.057–0.193% of pixels differed by more than 8/255. The direct Vello filter path accepts those multiple-shadow cases. One shadow mixed with blur and/or noise also passed guarded GPU stack fixtures; more than one shadow mixed with other effects remains unverified.

The direct opaque-path shadow now uses miter joins and butt caps, matching the reference spread band. Its offset is applied in document space so rotation does not rotate the shadow displacement. Ellipse, polygon and star fixtures passed spread 0, 3, 10, 20 and 32 at 1×/2×, including a rotated 32-unit case. A cached silhouette path covers visible strokes on rectangles, ellipses, polygons, stars, concave vectors, and lines, including outside strokes and dashed strokes at zero spread. Positive spread on dashed strokes and positive spread on text glyphs did not meet the reference threshold and remain guarded.

On 2026-10-30, `cargo xtask ci` passed with the four-effect stack, including the GPU module's 49 tests, workspace tests, layer checks, WASM checks, and plugin checks. The tests include six glass/blur/noise orders, glass plus drop shadow in both orders, rotated glass panes, rotated blur/shadow in both orders, longer blur/noise/shadow group stacks, the four-effect translucent pane at 1×/2×, and the expanded spread and mask cases. `gpu_icon_effect_parity` on the saved icon reproduced the prior 1×/2× mean RGB errors of 0.798/255 and 0.764/255, with 0.601% and 0.401% of pixels over 8/255. That run used an unoptimized benchmark profile, so its timing is not comparable to the earlier optimized numbers. These are parity fixtures, not proof that every document effect can leave the CPU path.
