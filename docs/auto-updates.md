# In-app updates on macOS

Lizard checks the latest **published stable** GitHub release in the background when a packaged `Lizard.app` opens, then checks again about every six hours while it stays open. If the version is newer, an in-app notice offers **Update**. That button downloads and verifies the installer; **Restart and update** becomes available after verification. Lizard asks the user to save edited files and close other Lizard windows before restarting. A temporary helper then replaces the app and opens the new version. The same controls are in Settings → General → Updates.

The updater reads `https://api.github.com/repos/brava-group/lizard/releases/latest`. The release must include `lizard-<version>-macos-aarch64.dmg` or `lizard-<version>-macos-x86_64.dmg`, depending on the running Mac. It ignores drafts and pre-releases. The installer must have GitHub's SHA-256 asset digest, a valid Developer ID signature for team `2L268W62AW` and bundle ID `com.brava.lizard`, and Gatekeeper approval. It checks the DMG and the staged app before replacing anything. Downloads use HTTPS only and have a 600 MiB limit. The installed app must be writable by the current user; otherwise the update stops without replacing it.

**Publishing requirement:** GitHub's release API and assets must be reachable without authentication. A private repository or a draft release returns no usable update to end users. Notarize and staple the app and DMG before publishing the release; an unnotarized package fails the updater's Gatekeeper check. The current `v0.9.1` draft is therefore not an update source. Follow [the macOS release checks](releasing.md#macos), then publish the release only after strict verification passes.

The standalone binary built from source and the browser build do not self-update. On macOS, a build from source can use Settings → General → Updates only when it runs inside `Lizard.app`; the same signature and Gatekeeper requirements apply to downloads.
