# Standalone UI component catalog

Run `cargo run -p workbench-ui-catalog` from the repository root. This starts **Workbench UI** as its own native desktop process and window. The Lizard editor does not start. To open a specific page, use `cargo run -p workbench-ui-catalog -- --page Glass`; `--audit` renders all pages headlessly. The reusable foundation is the independent `workbench-ui` crate under `crates/workbench-ui/`. Lizard adapts those controls to its theme in `crates/ui-egui`; the catalog is a separate workspace package under `apps/workbench-ui-catalog/` and is not part of the production app bundle.

The left sidebar switches pages and filters by component name or group. The Light mode button switches between the production light and dark tokens. Hover, menu, text, sizing, and slider states are interactive. The catalog builds a synthetic document in memory so the real workspace panels can show their selected, mixed, and empty states without opening a user file.

The **Cursor playground** page compares all current canvas cursor images with original vector proposals side by side. Filter by state or group, switch the preview canvas between dark and light, enlarge the artwork, and show each cursor's click point. This page is for visual review; the proposals are not wired into the editor.

The 83 pages separate **Primitives** from **Compositions** and larger workspace surfaces. The primitives include reusable controls from `widgets.rs` and `primitives::ColorControl`, all icon drawing families, a theme preview, and semantic color tokens. The composed pages include app menus and actions, the Share popover, document tabs, the tool toolbar, Pages/Layers, Assets, Agent welcome/conversation/running/history, Versions, Home, the Design panel with page/rectangle/frame/auto layout/text/vector/component/mixed selections, each Design-panel section on its own page, all six effect settings popovers, Prototype, Inspect, frame presets, comments, solid/gradient/image/pattern paint editors and the color library, style picker, variables, keyboard shortcuts, plugin manager, Preferences, About, Export, Find and replace, Rename layers, Create link, and Import report. These previews invoke the production UI functions; they do not redraw the controls in a separate style.

`theme::ColorRole` is the semantic palette used by Lizard's controls. Its `--lizard-color-*` names describe purpose, such as surface, selected text, or danger border; every role has explicit light and dark values. The **Color tokens** catalog page lists the roles with live swatches, searchable names and usages, and copyable hex values. The **Theme** page shows real button and text controls in both modes side by side. The source palette was adapted from [FigUI3's MIT-licensed `components.css`](https://github.com/rogie/figui3/blob/main/components.css), an independent UI library. Lizard keeps its own editor surfaces: dark panels use `#2B2B2B`, the dark canvas uses `#1E1E1E`, menus use a dark shell, and selected editor text uses white over `#255681` in both modes. These product choices are shown on the Theme page.

The **Iconography** page shows each general glyph once and identifies aliases in its hover label. Ordinary UI glyphs share a 78% painted extent inside their icon box, measured from the vector geometry rather than the SVG view box. Small glyphs are rasterized once at twice the display resolution with antialiased edges, cached as alpha masks, and tinted by the active theme. Tiny chevrons, the brand mark, toolbar compositions, Agent art, and panel-reference compositions retain their designed dimensions. The 78 panel-reference slots now reuse 27 uniquely named drawings; existing effect and color-picker indices still resolve to the same artwork.

The Layers tree follows `panels-design.pen` node `ScVXd`: a 40 px header, 4 px list top gap, 32 px rows, 8 px horizontal inset, 24 px indentation per level, and exact 16 px box vector icons for layer types. The header's collapse action uses the design's 24 px icon. The Pages and layers catalog preview is 328 px wide and shows image, star, polygon, ellipse, arrow, line, an expanded mask group, horizontal/grid/vertical auto layout, component instance, and group examples using real document nodes. Mask rows show a right-aligned status label; vertical connectors link their covered siblings and end in an arrow at the mask.

`ColorControl` is the first extracted primitive. It draws the swatch, value slot and opacity slot, then returns user intent (`open_picker`, edited hex, edited opacity, detach variable). It does not own document state. Fill, stroke, and effect rows compose it with labels, visibility/removal actions, picker targets, and engine commands. The hex and opacity editors share one focus outline; the trailing `%` is a separate, right-aligned scrub handle. Its dark appearance follows `panels-design.pen` node `wHJkI`: a 24 px field with `#383838` background and border only on hover; when a color variable is bound, the field becomes a single labeled button and shows a separate 24 px unlink button on hover. The catalog page shows editable solid, named gradient, bound variable, and disabled variants at the reference width of 156 px. The bound example uses a real color variable in the catalog's synthetic document, so unlinking and rebinding exercise the same commands as the editor.

`ColorValue::Model` adds the swatchless 144 × 24 fields from `panels-design.pen` node `Y0mRc`: Hex with a 45 px opacity slot, three numeric channels with the same opacity slot for RGB/HSL/HSB, and a full-width CSS `rgba(...)` field. The picker uses these same variants, and the catalog shows each model editing one shared sample color. Model edits report the resulting color and scrub completion to the caller; the primitive still owns no document state.

Text selection is set once in the global egui theme: white selected glyphs over `#255681` in both light and dark modes. Every egui text editor inherits it, including the catalog and the custom right-to-left name editor.

The number-field primitive in `widgets.rs` follows `panels-design.pen` node `BavO5`. Its 88 × 24 opacity variant uses the reference icon, 11 px medium text, `#383838` field, `#444444` hover outline, and variable action on hover. A bound number shows its resolved value in a compact chip (`#2c2c2c` normally, `#444444` on hover) and reveals the unlink action on hover. The primitive reports `BindEvent`; the variable picker is composed separately by the property panel.

`ControlWidth` is shared by `ColorControl::show_sized` and `NumberField::show`: `Fill` takes the width offered by the parent, `Fixed(points)` keeps the requested size, and `Hug` measures the current value and reserves room for built-in actions. Their catalog pages display all three modes. Existing numeric widget calls and fixed-width color control calls remain valid while panels migrate to the composable API.

`NumberField::options` joins an editable number and a preset menu trigger in one control. The trailing chevron uses the shared icon, while the whole field shares its fill and hover or focus outline. Typography uses it for font size; the Number fields catalog page includes the variant.

`primitives::Button` composes a visual variant (primary, secondary, danger and its lighter variants, ghost, link, input, property, or overlay), a behavior (action, toggle, select), content (text and optional leading/trailing icons, or icon only), alignment, size, width, and enabled state. The production `widgets::button` and `widgets::icon_button_at` now use this primitive. The Buttons catalog page shows each variant with live hover/press states, a working toggle and select menu, icon layouts, alignment, and width modes. Visual tokens and the variant model were adapted from [FigUI3's MIT-licensed core button](https://github.com/rogie/figui3); no FigUI3 icon asset or JavaScript is bundled.

`primitives::SegmentedControl` provides text or icon segments, equal or content-based widths, regular or large height, and `ControlWidth` sizing. Its selection surface slides for 150 ms by default and becomes instant when reduced motion is enabled. Pointer and arrow/Home/End keyboard input return the chosen index to the caller; the editor's existing `widgets::segmented` and `widgets::segmented_text` use it. The Segmented catalog page shows equal, fixed, auto-width, icon, and large variations. Its behavior and semantic colours follow [FigUI3's segmented control](https://github.com/rogie/figui3#segmented-control).

`primitives::Slider` covers the range, hue, opacity, delta, and stepper types in default and classic appearances. It accepts min/max, step, mixed or initial value, a reference value and custom ticks, optional editable text, placeholder, units, display transform, color, precision, disabled state, and `ControlWidth` sizing. Pointer dragging reports continuous values and a final commit; text and keyboard changes commit directly. In the classic delta state, the track has a blue segment from the white reference dot to the thumb; the fixed-size thumb has a blue center while moved and becomes solid white at zero, whether zero is centered or at the left edge. The classic numeric field sits eight points from the track. Stepper shows its selected range in blue and retains the tick marks. The Sliders page shows each type, delta with text, classic states, width modes, mixed and disabled states. Production `widgets::slider` delegates to this primitive while retaining its existing call signature. The API and base appearance were adapted from [FigUI3's Slider](https://github.com/rogie/figui3#slider); the classic delta and filled stepper states follow the owner's visual reference.

`primitives::Tabs` renders compact 24 pt content tabs with selected, hover and disabled states, an optional empty selection, `ControlWidth` sizing, arrow/Home/End keyboard selection, and horizontal overflow with buttons or faded edges. Callers own the selected index and compose the corresponding content; the primitive returns the next index. The right property header and the About, Shortcuts and Plugins dialog strips use it. Document tabs keep their separate draggable, closable control. The catalog Tabs page shows default, single, content, disabled, widths and both overflow modes. The styling and interaction pattern follow [FigUI3's Tabs](https://github.com/rogie/figui3#tabs).

`primitives::ShimmerText` renders animated text with a light band that travels left to right. It supports horizontal, vertical and diagonal directions, cycle duration, play/pause, font size, semantic or custom colors, and `ControlWidth` sizing with wrapping. The Shimmer text catalog page previews the default 1.5-second treatment, the linked 0.6-second diagonal treatment, all directions, and the paused state. The treatment follows [FigUI3's Shimmer](https://github.com/rogie/figui3#shimmer).

`primitives::Surface` owns the rounded menu and Actions-palette shells, including their top inset highlights and shadow treatments. The Menu and Actions palette use the same surface API with different variants; the catalog Surface page previews both. `primitives::SearchField` supplies the icon-led 32 pt search input in the palette. The palette composes `Surface`, `SearchField`, `Tabs`, and the 32 pt palette variant of `MenuItem`; its size and spacing follow Pencil node `i1UCns`.

`primitives::Menu` supplies the common dark popup surface for anchored and context menus. `MenuItem` composes labels, shortcuts, checkmarks, leading/trailing icons, disabled rows, and subtle hover. It reports clicks and leaves selection state and commands with its caller. The existing `right::menu_popup`, `menu_item`, and `menu_check` helpers delegate to these primitives; selection menus in the property panel, color picker, and prototype player use the same surface and rows. The 13 px popup radius, 5 px inset hover shape, 11 px labels, menu tokens, and click-outside dismissal also apply to the stroke-sides selection menu. The Menu catalog page includes default, checked, grouped, disabled, icon, subtle-hover, and context-menu examples. This treatment follows [FigUI3's Menu](https://github.com/rogie/figui3#menu).

`primitives::Select` composes the shared Menu and MenuItem with a closed value trigger. `SelectPosition::Overlay` is the default: the popup has the trigger's width and left edge, with its selected row centered over the trigger. Six explicit positions place the menu above or below, aligned left, center or right. `ControlWidth` gives the trigger `Hug`, `Fixed` and `Fill` widths; `Hug` fits the widest option and fixed-width options elide when needed. `SelectVariant::Ghost` removes the resting field background and uses a secondary hover fill. The Select catalog page exercises these options, leading icons and color dots. Property fields, the sizing menu inside number inputs, and toolbar tool choices use the same selection primitives. Custom option menus use `Select::trigger` and `Select::popup_for`; the old dropdown trigger was removed. This follows [FigUI3's Select contract](https://github.com/rogie/figui3#select).

The fixtures are local to the catalog process and are discarded on exit. For popovers and dialogs, **Reopen preview** restores a closed preview. Add a page when a new reusable component or a new meaningful panel state is introduced; keep the source function in the page subtitle so visual changes remain traceable.

`primitives::FloatingPanel` provides the shared 13 pt rounded surface, border, shadow and draggable header for extended property controls. `show_with_header` reserves the drag area and lets each caller compose its own title, tabs, actions and exact SVGs; `close_button` adds a consistent hover state without replacing the caller's icon. Compact (240 pt), regular (304 pt), wide (400 pt), and explicit widths support fixed or content height. Effects, every color picker view, the style browser, corner smoothing, stroke settings, export and PDF settings, type settings, and the prototype interaction editor use this surface. The catalog shows title, tabbed and action headers in draggable size variants.
